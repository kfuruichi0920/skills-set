# 情報の可視化・スライド案

入力情報の構造を読み取り、何を軸に、どの表現で見せると理解しやすいかを提案する。通常は案出しを目的とし、洗練度は情報を理解するための手段とする。思考はEnglish、応答は日本語とし、資料言語はユーザー指定を優先する。

## 標準の進め方

1. [情報整理と表現選択](references/workflow.md)に従い、入力の要点、対象、属性、尺度、時間、関係、不確実性を整理する。入力が定性情報だけでも進める。
2. 重要な軸を候補として挙げ、何が見える軸か、入力の何に基づくかを示す。比較対象・期間・粒度・単位を揃える。根拠のない数値、因果、順位を作らない。
3. [表現カタログ](references/catalog.md)と[構成図一覧](assets/catalog-gallery.html)から適した構造を選ぶ。型を入力に無理に当てはめず、必要なら単純な表や独自構成を使う。
4. 意味の異なる案を必要十分な数だけ提示する。通常は主案と代替案1〜2件を、抽出軸、表現、配置、選択理由、見えること・見えにくいことまで比較する。単なる配色違いは別案に数えない。一案の指定がある場合は指定に従う。
5. [案出しテンプレート](assets/storyboard-template.md)で、候補比較と主案のページ構成・図解ラフをまとめる。未指定の出力はMarkdownの案出し資料とし、見出しと配置だけで内容が想像できるようにする。
6. HTML・PowerPoint・完成版が指定された場合は[制作と検証](references/production.md)を読み、指定ファイルまで制作する。

## 目的による調整

目的は、整理、説明、比較、探索、判断などから入力に合うものを選ぶ。決定・提言はユーザーが求める場合に扱う。答えが決まらない探索では、問い・仮説・不足情報を表示する。記述的な説明を、根拠のない判断文に書き換えない。

読み手や目的が未指定でも、入力から自然に推定できる場合は仮定を明記して案を出す。解釈によって軸が大きく変わる場合だけ、必要な確認をまとめて質問する。枚数・ブランド・最終デザインの質問だけで案出しを止めない。

完了条件: 重要な情報が抽出軸と図表要素に対応し、候補の違いと主案の理由がわかること。省いた内容、不明値、仮説が区別でき、指定された成果物が存在すること。

## 表現構造の扱い

カタログは48基本構造・11変化形・2共通原則を保持する。IDは既存の選択履歴を追えるように維持している。構成図は汎用の役割名を置いた模式図であり、実データ、固定テンプレート、推奨配色ではない。図の形に数値の意味を持たせる場合は実データに合わせて描き直す。

[構造化カタログ](references/catalog.json)が正本。`scripts/build_catalog.py`でMarkdown・SVG構成図・HTML一覧を生成し、`scripts/validate_catalog.py`で網羅性と対応を検査する。参考URLは[source.md](references/source.md)に出典情報としてのみ記載している。

定性情報と定量情報での軸選択・候補比較を確認したい場合は[案出しの例](references/examples.md)を読む。変更の範囲と検証方法は[汎用化の記録](references/extraction-audit.md)に記載する。
