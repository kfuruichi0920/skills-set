# 意思決定のためのスライド

読者が判断するために必要な情報を、素材から選び、根拠を追える資料にする。思考はEnglish、対話と資料は日本語を基本とし、ユーザーが指定した資料言語を優先する。

## 1. 入力と判断対象を整理する

読み手、求める判断、素材、出力形式を既存の会話とファイルから確認する。判断対象や読み手によって内容が大きく変わるときは、不足事項をまとめて質問し、回答に依存しない素材整理を進める。

枚数は素材と発表時間から調整する。未指定の出力はMarkdown設計図、画面比率は16:9とする。既存テンプレート、ブランド、ユーザー指定を優先する。

素材の数値・引用・出来事について、元ファイルのページ、URL、対象期間などの出所を記録する。事実、試算、仮説を区別する。未知の値は「要確認」とし、試算では式と前提を示す。

完了条件: 判断対象を一文で書け、主要な根拠と不足情報を区別できる。

## 2. ページの役割を設計する

資料全体の提案と、読者が判断するための問いを整理する。各ページに問い、答え、証拠を割り当て、見出しだけを読んでも提案までの筋道が追えるようにする。

見出しは、そのページで支持できる主張を一文で示す。素材の確かさに合わせて断定の強さを調整する。比較する選択肢は同じ基準と期間で評価し、利点と制約を扱う。判断を求める資料の最後には、求める決定と次の行動を置く。未確定の担当・期限はそのまま明示する。

設計図には以下を含める。

- 全体の提案、読み手、判断事項、前提、不足情報。
- ページごとの問い、主張、根拠と出所、図表の選択理由、配置。
- 求める決定、その判断基準、次の行動。

完了条件: 各主張が素材または明示した仮説に対応し、重複と論理の飛躍を解消している。

## 3. 伝える関係に合わせて図表を選ぶ

量の比較は棒、時間の変化は折れ線、内訳と増減は積み上げやウォーターフォール、選択肢の評価は比較表、工程や責任はフローやレーンを候補にする。情報量と読み手に応じて最も読み取りやすい表現を選ぶ。因果関係は素材が裏づける範囲で示す。

比較図は尺度、単位、配置を揃える。棒や面積で量を表す場合はゼロ基準と比例関係を保つ。折れ線などで軸を省略する場合は範囲を明示し、変化を誇張しない。実績、予測、目標は凡例またはラベルで識別する。

ブランド指定がなければ白背景と濃い文字を基本に、主張の根拠を一つの主色で強調する。ページ内の主張、図表、注記の階層を揃え、通常の投影で読める文字サイズを使う。参考記事の詳細規定を忠実に適用したい場合は[参考元](references/source.md)のリンクを確認し、今回の指定範囲で適用する。

完了条件: 図表から主張の根拠を読み取れ、数値表現と凡例に矛盾がない。

## 4. 指定形式で制作する

設計だけの場合は、上の設計図をMarkdownファイルとして保存する。

HTMLまたはPowerPointの場合は[制作と検証](references/production.md)を読み、利用可能なツールで実ファイルを作る。設計は制作前に内部で固め、ユーザーが途中確認を求めている場合に提示する。設計だけの提出を完成ファイルの代わりにしない。

## 5. 提出前に確認する

主張と証拠の対応、数値の整合、出所、不足情報の表示を確認する。制作物はレンダリングして全ページを見て、文字の欠け、重なり、改行、余白、色の判別を修正する。検証できなかった項目はその範囲を明示する。

完成ファイルへのリンクと、残っている要確認事項を簡潔に伝える。ユーザーが指定した出力範囲に合わせる。
