# 意思決定スライド

本スキル内の工程・規準・表現カタログで制作を完結する。参考URLは由来を示す情報であり、通常の制作でアクセスする必要はない。思考はEnglish、対話と資料は日本語を基本とし、ユーザーの指定を優先する。

## 入力と実行順

読み手、求める決定、素材、枚数、出力形式、ブランド指定を会話とファイルから整理する。判断に影響する不足だけをまとめて質問する。未指定の形式はMarkdown設計図。数値の出所・期間・単位を記録し、素材にない値は`xx`、試算は式と前提を示す。添付見本の数字・社名は架空のモデルであり、制作対象の事実として使わない。

1. [工程と規準](references/workflow.md)を読み、言い切る → 論理を組む → 型を引く → 規準で描く → 計測で検証の順に進める。
2. 型を選ぶ工程で[表現カタログ](references/catalog.md)を読む。48型、11追加変化形、2共通原則を名称・用途・配置・記号・注意点から選ぶ。
3. 選んだ見本は[ローカル見本一覧](assets/catalog-gallery.html)またはカタログにある画像で確認する。基本型と変化形は別IDで記録する。
4. [設計図テンプレート](assets/storyboard-template.md)の項目で構成と証拠対応を保存する。途中確認を求められている場合はここで提示する。
5. HTML・PowerPointを指定された場合は[制作と検証](references/production.md)を読み、完成ファイルまで作る。

完了条件: 見出しの縦読みで結論が追えること、各主張を根拠に対応付けられること、数字に出所または試算前提があること、指定形式の実ファイルを提出できること。視覚検証ができない場合はその範囲を明記する。

## カタログの再利用と保守

機械処理では[構造化カタログ](references/catalog.json)を使う。見本の切り出し座標、元画像の行列、基本型・変化形・原則の区分を含む。`catalog.json`が正本で、Markdown一覧・見本画像・HTML一覧は`scripts/build_catalog.py`で生成する。

カタログの追加・変更後は`scripts/validate_catalog.py`でID・件数・画像対応・生成物との一致を検査し、元画像を見て名称と表現を再照合する。[抽出と再点検の記録](references/extraction-audit.md)に結果を記録する。

画像にある元作者の品質・生成枚数・検査スクリプトの記述は由来の情報であり、このスキルで実証した品質や付属ツールとして扱わない。由来は[参考元](references/source.md)に記載する。
