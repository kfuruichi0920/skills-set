# 制作と検証

HTMLまたは編集可能なPowerPointを作る場合に読む。

## ツールの選択

HTMLは標準HTML/CSS/SVGで作成し、PowerPointは利用可能な`python-pptx`やPptxGenJS等のライブラリで作成する。以下の手順で本スキル内で完結する。環境固有のレンダラーがある場合は、そのツールの手順を使う。

Codexデスクトップでは`load_workspace_dependencies`で実行環境とライブラリを確認する。存在しないツールやレンダラーを使えたものとして報告しない。必要な環境が使えない場合は、完成できる範囲と不足条件を示し、途中成果を保持する。

## HTML

ユーザー指定がなければローカルで開ける単一HTMLにする。各スライドを1920×1080の独立した`section`とし、画面表示と印刷でページ境界を保つ。図表はSVGで絶対配置し、テキストも編集できる要素にする。フォントはNoto Sans JPやYu Gothic等の日本語フォントで統一し、ネットワーク依存のフォントには代替を設定する。

閲覧用ナビゲーションを設ける場合はキーボードでも操作できるようにし、印刷時はナビゲーションを隠す。縮小表示で文字が欠けないように、スライド全体の比率を維持する。

ブラウザーで全ページを確認する。外部フォントを使用する場合は、読み込み完了後に確認し、代替フォントでも崩れないか確認する。

PNG出力は必要に応じて2倍の3840×2160で保存する。PDF出力は各sectionを一ページにし、ブラウザーのヘッダー・フッターを無効にする。PNG・PDFへの書き出しは依頼された場合に行う。

## PowerPoint

環境にあるPPTX作成ライブラリを使う。本文はテキスト、図は標準図形や編集可能なグラフとして作り、ページ全体を一枚の画像にしない。写真など画像が適切な部分には画像を使う。

HTMLやSVGの座標を流用する場合は、スライド幅・高さに対する比率で変換する。pxとptを固定の比率で変換すると意図しないページ寸法になり得るため、PPTX側のサイズから換算する。

工程図のpx÷2＝ptをそのまま採用する場合は、ページを960×540pt（13⅓×7½インチ）に設定する。この場合ヘッド48pxは24pt、本文20pxは10pt、最小18pxは9ptになる。投影時に小さい場合はユーザーの用途に合わせて大きくし、情報量を減らす。標準の13⅓×7½以外のページを指定された場合は幅と高さから再換算する。

テーマのaccent1を主役色にし、階調や文字色を含むテーマの12色スロット（dk1・lt1・dk2・lt2・accent1〜6・hlink・folHlink）への割り当てを管理する。色を固定RGBだけで描くとテーマ変更に追従しないため、主役・階調の図形にはテーマ色とtintを設定するか、生成時に配色パラメーターから全ページを更新する。後者は「再生成による変更」と明記し、PowerPoint上のテーマ変更と区別する。

文字はYu Gothic等で統一し、影を付けない。テーマ変更を対応機能として提出する場合は、主役色を別色に変えて文字・図形・グラフの追従を確認する。確認できていない機能を対応済みと報告しない。

生成したPPTXをPDFまたは画像にレンダリングして全ページを確認する。日本語フォントの代替による改行も点検する。レンダラーが使えない場合はファイル構造の検査を行い、見た目の確認が未実施と明記する。

## 検証記録

制作を完了したか、内容を確認したか、全ページを視覚確認したかを区別する。数字の合計、比率の分母、期間と単位の整合を確認する。修正したページは再確認し、解消しない問題を完成扱いにしない。

見出し8検査と配置4原則は`workflow.md`を正本とし、ここでは検査対象の実ファイルを扱う。提出物には設計図、指定された完成ファイル、検証結果と未達を含める。途中の設計図を別提出しない指定の場合は、内部成果として保持する。
