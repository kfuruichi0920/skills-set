# 工程と規準

添付工程図を工程別に構造化した運用規準。図中の「上司の教え」は各工程の意図として記録する。ユーザーの指定がある場合は指定を優先し、規準からの差分を記録する。

## 工程1: 言い切る

入力: 素材、読み手、求める決定。出力: 各ページの問いとヘッドメッセージ。図はこの段階では作らない。

見出しの5規定:

1. 主語・述語を持つ完全文にする。
2. 一枚一メッセージとし、事実と判断を一文に持つ。
3. 30〜60字を目安に、まず一行36字幅で設計する。字数と実際の表示幅は別に確認する。
4. 数字は主張を支える実質値のみ、最大2つにする。
5. 二段構え、要素の数え上げ、体言止め、ダッシュ、自己言及を避ける。

6文型を使い分け、隣接3枚で同型を続けない。

| 文型 | 形 |
| --- | --- |
| 因果 | 〜のため、〜する |
| 条件 | 〜すれば、〜が固まる |
| 逆接 | 〜だが、問題は〜にある |
| 起因 | 〜を左右するのは〜ではなく〜だ |
| 評価 | 〜は〜の範囲にあり、〜を左右しない |
| 提言 | 〜に、〜を集中させるべきだ |

執筆手順は、問い → 判断 → 支える事実 → 接続語で一文にする。工程図では45字程度から36字に削り、根拠節、修飾語、主語の順で短くする。主語を削る際も何についての判断かを曖昧にしない。一行に収まらない場合は文節で二行にし、判断を保つ。図表の説明をそのまま見出しにせず、事実の意味を述べる。

逆テスト: 本体だけから同じ見出しが書ける場合、判断が十分か再点検する。示唆は見出しに置き、下部にSo What帯を重ねない。決定ページに限り論点ボックスを設ける。

意図: メッセージを先に定める。完了条件: 各見出しに問い・事実・判断が対応し、工程5の見出し検査に通る。

## 工程2: 論理を組む

複数枚の場合は資料全体の結論を一つ定め、見出しの台帳を先に作る。一枚物ではページ間の検査を省略する。

| 論理構造 | 接続の意味 |
| --- | --- |
| 順序 | Step、時系列、工程の順 |
| 比較 | As-is／To-be、選択肢、対立 |
| 分類 | 同じ切り口の区分、MECE、マトリクス |
| 問題解決 | 問題 → 打ち手 → 効果 |
| 因果 | 原因 → 結果。因果の裏付けが必要 |
| ピラミッド | 結論を複数の根拠で支える |

台帳の項目: No、問い、ヘッド、文型、上位への集約、直前からの接続語、本体の型と見本ID、MECEを確認する相手、論点、強調点、覚えて帰る一点。

縦の検証は「だから／なぜなら」でつながり、論理の飛躍がないこと。横の検証は同階層を一つの切り口で分け、粒度を統一すること。判断事項は資料全体で3〜6個を基本に、冒頭の型02で番号を予告し、末尾の型03で同じ番号を回収する。小規模資料では無理に論点を増やさない。最終ページに決定事項・日程・判断基準を置く。

工程図は制作前の設計に約7割の比重を置き、完成後の縦横点検を最大3周としている。時間配分の目安であり、事実の裏付けを省く理由にしない。

意図: 資料を判断につなげる。完了条件: 見出しだけで結論を再構成でき、判断事項が冒頭と末尾で一致する。

## 工程3: 型を引く

グラフ名より、メッセージが何をさせたいかで7用途から選ぶ。

| 用途 | 型番号 | 基本型数 | 見本数 |
| --- | --- | ---: | ---: |
| 決めさせる | 01〜06 | 6 | 8 |
| 分解する | 07〜13、46 | 8 | 10 |
| 比べる | 14〜19、45 | 7 | 11 |
| 変化を見せる | 20〜22 | 3 | 4 |
| 関係と位置で見せる | 23〜34 | 12 | 14 |
| 時間と工程で見せる | 35〜40、47 | 7 | 7 |
| 構造を地図化する | 41〜44、48 | 5 | 5 |
| 全型に効く原則 | 型番号なし | 0 | 2 |

各型の用途・配置・線と塗り・注意点は`catalog.md`に記載する。見本の配置を骨格として再利用し、言葉と数字は今回の素材に置き換える。複数の型を合成するのは単独では伝えられない場合に限り、採用理由を残す。

型が合わない単純なページでは12グラフから選ぶ: 棒、折れ線、滝、ファネル、バブル、ヒートマップ、面積図、散布図、ベン図、積み上げエリア、サンキー、円。円は原則避け、5項目以下で過半の判定が目的のときだけ検討する。

証拠対応表で見出しの各節を図表のどの要素が証明するか示す。文字注記だけで主張を支える場合は、図表化するか主張を限定する。数字は出所つき実データか前提を明記した試算に限り、不明値は`xx`で保持する。

意図: 言い切った主張に証拠を付ける。完了条件: 全ページに型と見本ID、選択理由、証拠対応がある。

## 工程4: 規準で描く

配置の4原則:

1. 縦横の軸を先に決める。
2. 共通する記述を見出し・軸へくくり出し、冗長さを減らす。
3. 一つの図を二次元で読めるようにし、第三軸が必要なら分割する。
4. 量を表す長さ・面積・太さを量に比例させる。

軸ラベル・単位・固有名の繰り返しは読み取りに必要な範囲で残す。比較図は位置と尺度を保つ。規準を変える場合は理由を設計図に残す。

| 記号 | 共通の意味 |
| --- | --- |
| 実線 | 実績・確定 |
| 破線 | 予測・計画・消える要素 |
| 点線 | 補助輪郭 |
| 塗り | 実績・自社 |
| 枠のみ | 計画・目標 |
| 濃色／淡色 | 主役／文脈 |

フローでモノ・金・データを区別する場合は、実線・破線・点線を使い、ページに凡例を置く。時制の意味と混同する場合はラベルや線色を補い、同じ線に相反する意味を持たせない。

標準キャンバス: 1920×1080。上下余白62px、左右86px。ヘッド48px、二行は44px、図表タイトル24px、本文20px、注記を含め最小18px。図表ごとにタイトルを付ける。下部は下からフッター → 注記 → 論点ボックス → 本体の順に積む。

標準配色: 主役`#1976D2`、階調`#5E9FE0`・`#98C1EB`・`#C6DDF4`、パネル`#EEF3F6`、罫線`#D9DEE3`、本文`#222222`、注記`#6B7C85`。工程図にある「5色」は主役・階調3色・パネル地の役割を指し、全使用色数の上限とはしない。ブランド色がある場合は主役色を置き換え、白を28・52・75%混ぜた階調を作る。強調色は既定では使わず、使う場合はデッキ全体で一箇所を目安にする。

グラフは単位・時点・実数ラベル・出所を示す。並列図の軸範囲と目盛を揃え、実績と予測の境界を明示する。棒・面積はゼロ基準を守り、折れ線等で軸範囲を限定する場合は明示する。系列名を図の近くに置き、補助線を必要最小限にする。表の列幅は長いセルから決め、語の途中で折り返さない。

装飾アイコン、3Dグラフ、全幅カラーバーを既定では使わない。表・本文・注記のダッシュを空欄の埋め草にしない。影を除去し、日本語フォントを統一する。

意図: 色は役割を持たせ、線の文法を最後まで保つ。完了条件: 全ページの規準と記号が揃い、型の配置が主張を支える。

## 工程5: 計測で検証

見出しの8検査:

1. 二文や二段構えになっていない。
2. 要素を数え上げるだけの文になっていない。
3. 実質数値が二つ以下である。
4. 判断語があり、根拠に対して過度に断定していない。
5. 主語・述語を持つ完全文である。
6. 字数と表示幅を測り、実際の描画で収まる。
7. 「本ページ」などの自己言及がない。
8. 同じ文型を三枚連続で使っていない。

レイアウト検査: 最小18px、ダッシュ0、テキストの実測幅または幅見積り、はみ出し・重なり・ラベル欠け・孤立改行を確認する。工程図の最大空白矩形12%以下は本体領域を対象とした目安とし、意図的な余白を除外した測定領域・方法を記録する。測定器がない場合は「未計測」とし、目視を計測済みと扱わない。

内容検査: ヘッドの数字と本体の合計が一致し、比率の分母・期間・単位が揃い、見出しの縦読みと並列要素の粒度が通ることを確認する。修正を一周行い、収まらない場合は実装を詰め込まず設計に戻る。

図中の`head_check`・`layout_check`は元作者の検査名であり、その実装は提供されていない。本スキルでは上記をチェックリストとして実行する。機械検査を新設する場合は、正例と意図的に壊した例の双方で検査自体を確認する。

意図: 正確さを必要条件とし、最終的に人が判断できるかを見る。完了条件: 検査結果と未達項目を記録し、指定形式の完成ファイルを出せる。
