# 情報整理・可視化

入力を整理し、第三者が意味・関係・条件を理解できる資料にする。スライドはキャンバスの一候補。思考はEnglish、応答は日本語とし、資料言語はユーザー指定を優先する。記述は[日本語の規則](references/japanese-writing.md)に従う。

## 実行条件

- 通常の利用では成果物を`output/YYYYMMDD_HHMMSS_約20文字の日本語概要/`へ保存するだけとし、Gitの確認・add・commit・pushを行わない。スキル定義や版管理サンプルの改修は別の作業であり、リポジトリの規則に従う。
- 既存outputは明示指定された対象以外を列挙・検索・参照しない。今回作成したパスだけを記録して制作・読戻し・修正する。生成スクリプトと依存ファイルも保存する。
- [実行モード](references/execution-modes.md)を選ぶ。未指定は高速モードとし、開始時に伝える。精密モードの指定、または個別検査の追加・省略指定を優先する。
- 形式未指定ならMarkdown中心＋補足図＋大きな表はTSVを推奨して希望を質問する。HTMLスライド、CSV、その他の明示指定にも従う。確認済みの質問を繰り返さない。

## 手順

1. 質問原文・入力時刻・出所を[根拠様式](assets/rationale-template.md)へ記録する。素材を情報単位に分け、事実・解釈・仮説・不明を区別する。目的や読み手は未指定なら仮定を示す。曖昧さが関係や条件を変える場合は確認する。
2. 「目的 → 意味・整理軸 → 表現 → 専門手法 → 説明」を選ぶ。[整理体系](references/framework.md)と[選択規則](references/selection-rules.md)は該当部分だけ読む。16目的・19軸・12表現や既存カタログを閉じた選択肢にしない。時間と順序、処理と状態、相関と因果を区別する。
3. 比較・対応・分岐・全体と詳細があるまとまりは図解候補を検討する。[構成選択](references/catalog-selection.md)から必要な型だけ参照する。Draw.ioは[ボキャブラリー](references/diagram-vocabulary.md)で説明パターンを検索し、[ネイティブ機能](references/drawio-native.md)で実図形を選ぶ。シーケンスはPlantUML。既存図・画像への説明追加は[注釈モード](references/visual-annotation.md)を使い、原図を保持する。
4. [テーマ](references/diagram-themes.md)を目的と読み手から選び、図の型・色形線の意味・配置を分ける。[制作・保存](references/production.md)に従って指定形式を制作する。高速モードでは不要なプレビューや全カタログの再検査を行わない。
5. 選んだモードの検査を行う。整理結果と根拠Markdown、編集可能な図、必要な表・生成用ファイルを保存し、主成果物のリンクと未実施の検査を示す。

## 完了条件

重要情報・条件・例外・多対多関係を保ち、入力と出力要素、採用理由、省略・不明点を追えること。未知の数値・因果・順位・評価重みを作らない。正式な専門分析や規格準拠を求められた場合は対象版と必要入力を確認する。

両モードで意味とファイルの整合を確認する。精密モードでは[配置検査](references/drawio-layout-check.md)も完了する。高速モードの成果物は「詳細な目視検査は未実施」と明記し、表示検査済みと報告しない。根拠を省略・別形式にする明示指定は尊重する。

## スキルの改修時

出力仕様を変えた場合は[サンプル更新手順](../../../sample/information-structuring/README.md)に従い、対応する図・原図・IR・生成コード・一覧を同期する。通常の利用でサンプル再生成やリポジトリ全体の検査は行わない。詳しい工程は[workflow.md](references/workflow.md)、適用例は[examples.md](references/examples.md)を必要に応じて参照する。
