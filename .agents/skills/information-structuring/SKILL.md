# 情報整理・可視化

目的は、入力情報を解析・整理して、第三者に正確かつ理解しやすく説明できる状態にすること。スライドのフォーマットは情報をまとめるキャンバスの一候補として使う。スライド枚数や完成デザインより、意味・関係・整理軸の妥当性を先に確かめる。思考はEnglish、応答は日本語とし、資料言語はユーザー指定を優先する。

本スキルの指示文・参照文書・テンプレートを改訂するときも、日本語の成果物・図表ラベル・補足を書くときも、[日本語の記述規則](references/japanese-writing.md)を読む。正確性を保って短く書き、主語・対象・条件・結果、記述の役割、用語と根拠を明示する。

## 実行手順

出力はMarkdownを優先し、補足図はシーケンス図にPlantUML、構造・配置図にDraw.ioを使う。大きな表・マトリクスはTSV（CSVも可）で添える。未指定なら[出力形式と保存規則](references/production.md)に従い、この組合せを推奨して希望を質問する。回答待ちの間は入力の整理を進め、形式に依存する制作は回答後に行う。

1. [整理の工程](references/workflow.md)を読む。[根拠記録テンプレート](assets/rationale-template.md)の入力記録に質問原文と入力時刻を残す。その後、素材を出所付きの情報単位に分け、対象・定義・属性・関係・条件・確かさを整理する。
2. [整理体系](references/framework.md)の16目的・19基本軸・12基本表現から該当する観点を選ぶ。複数目的やファセット分類を許し、この一覧も閉じた選択肢にしない。
3. [選択ルール](references/selection-rules.md)で「整理目的 → 意味・整理軸 → 基本表現 → 必要な専門手法 → 説明方法」を選ぶ。概念の混同、時間と順序、処理と状態、相関と因果を先に区別する。
4. [可視化の規則とASCII図の型](references/visualization.md)を読み、複雑な情報は、比較位置・レーン・全体と詳細の分け方を参考に可視化する。図の種類に応じてPlantUML・Draw.io・ASCIIを選ぶ。候補ごとに見える関係、前提、不足を比較する。既存61構造の[表現カタログ](references/catalog.md)と[構成図一覧](assets/catalog-gallery.html)は配置の参考として、合う場合に読む。一覧外の整理方法、複合表現、独自構成も同じ基準で候補に含める。型に情報を合わせて欠落させない。
5. [成果物テンプレート](assets/storyboard-template.md)を使い、整理結果、軸と表現の比較、主案のラフを組み立て、確認した出力形式へ変換する。
6. [根拠記録テンプレート](assets/rationale-template.md)を使い、入力の出所 → 正規化した情報 → 検出軸 → 候補 → 採否理由 → 出力要素の対応を、別の補足資料として保存する。
7. [制作と検証](references/production.md)に従い、作業対象のルートの`output/YYYYMMDD_HHMMSS_約20文字の日本語概要/`に、主成果物・図・整理根拠などの出力結果をまとめて保存し、リンクを提出する。

## 出力と完了条件

確認した形式で整理結果と可視化を出し、整理根拠の補足Markdownを添える。補足を省略・別形式にする指定がある場合は従う。根拠記録には検証可能な観測事実・適用条件・選択理由・留保を記す。

目的や読み手が未指定なら、入力から推定した目的と読み手を仮定として記す。対象の意味・条件・説明目的が複数に解釈でき、採用する軸や関係が変わる場合は、解釈を確定するための質問をまとめて行う。出力形式の確認はproduction.mdに従う。未知の数値、因果、順位、評価重み、要求と検証の対応を作らない。

完了条件: 入力の重要情報が整理結果と表現要素へ対応し、条件・例外・多対多関係を保ち、目的と読み手に適した説明ができること。主案の理由、代替案の条件、省略、不明点が補足資料で追えること。

## 体系とカタログの扱い

16目的は情報整理の観点、19軸は情報の意味、12表現は構造、専門手法は目的・領域の意味づけ、説明方法は読み手向けの伝え方である。希望する出力形式は早めに確認し、情報整理と表現選択の後に、その形式に適したキャンバスと配置を決める。

専門手法は候補として扱い、必要な入力や記法を満たす場合に採用する。規格準拠・正式記法・計算アルゴリズムを求められたときは、対象版と一次資料を確認して扱う。概略の整理を完全な専門分析や規格準拠と報告しない。

機械処理は[整理体系JSON](references/framework.json)と[構造カタログJSON](references/catalog.json)を使う。体系は`scripts/build_framework.py`、構成図は`scripts/build_catalog.py`で生成する。検査は`scripts/validate_framework.py`と`scripts/validate_catalog.py`。選択と補足の例は[適用例](references/examples.md)、由来と変更記録は[source.md](references/source.md)・[検証記録](references/extraction-audit.md)にある。
