# カタログから図解を選ぶ

整理軸を抽出した後、各情報のまとまりに対して本書の索引を照合する。該当する型はcatalog.json／catalog.mdで用途・軸・必要情報・配置を読み、catalog-gallery.htmlまたは対応するSVGで構成を確認する。カタログは図解候補の起点とし、適合しない場合は一覧外・複合表現を選ぶ。

## 図解を作る条件

次の特徴があり、図の目的・対象・関係を入力から特定できる場合は、確認済みの出力形式に合わせて図を制作する。Markdown優先の指定は本文形式の指定であり、補足図の省略理由にはしない。

- 複数対象を同じ観点で比べる、または変更前後の差を説明する。
- 階層だけでなく、層・役割・工程への対応や被覆・空白を示す。
- 処理の分岐・受け渡し・担当の違い、または複数の関係を示す。
- 全体と重点部分、共通点と相違点、重複や補完を同時に説明する。
- 数値の内訳・増減・分布・時系列・複数指標の関係を示す。

入力が単純な定義・短い列挙だけの場合は文章でよい。単一の包含階層や直線的な処理順だけならASCIIを使える。図を省く場合は、どの入力の特徴を点検し、文章や表で何が十分に理解できるかを根拠資料へ残す。情報不足の場合は不足項目を示し、分かっている関係だけを図にできるか検討する。

## 入力の特徴と型の索引

下記は候補を探す索引。IDの正本はcatalog.json。定量表現の値・比率・境界は入力にある場合だけ使う。

| --- | --- | --- |

| 同種対象を共通観点で比較 | 04・14・16・19・45（横並び） | 同じ順序・位置で差を示す。数値がなければ定性ラベルで比較 |
| 同じ工程、フロー、組織の違い | 15・17・18 | 同型の並置。対応する段階・役割を揃える |
| 現状と変更後、前提の転換 | 20・22 | 同位置Before/After、前提と新方針の対応。変更根拠を併記 |
| 規模・構成の転換 | 21（残像含む） | 面積と差分。規模・割合の値が必要 |
| 合計の増減、歩留まり、分配 | 07（上下並列含む）・08・09（三層含む）・10・12・13 | 合計・内訳・段階を対応。量、単位、分母、計算関係が必要 |

## 候補比較から制作へ

1. 各まとまりについて、入力の特徴、読者の問い、カタログ候補IDを記録する。比較や対応を読みたい場合は、最初から一般的な箱と矢印へ固定せず、同型並置・同位置比較・レーン・地図・全体と拡大を照合する。
2. 候補の必須情報、見える関係、失われる条件を比較する。必要情報を満たす型を採用し、不足する型は保留する。複数の型が有効なら、主案と補助ビューの役割を分ける。
3. 入力IDを、型の領域・ノード・軸・関係名へ割り当てる。型を定性情報へ適用する場合は、均等な箱にラベルを付けるなど、数量を暗示しない配置にする。変更した意味と配置を記録する。
4. 選択した構造・配置図はdiagram-themes.mdでテーマと意味記号を決め、Draw.ioの図形・テキスト・接続線で制作する。SVG見本の貼付、カタログ画像の転載、ASCIIラフ、採用予定の文章だけで制作完了にしない。シーケンス図はPlantUMLを使う。
5. 採用ID、配置への適用内容、元情報ID、図のページ名、ファイルを根拠資料で対応付ける。複合図は使用した型をすべて示す。カタログ外ならその旨と選択理由を記す。

## 完了条件

図解対象のまとまりごとに、図ファイルまたは省略・保留の根拠がある。採用図には関係名・条件・凡例と元情報の対応があり、カタログの配置方法が何を理解しやすくしたか説明できる。表を箱へ移しただけなら、比較位置・層・レーン・共通部分・焦点の分け方を再点検する。

具体例は[同位置比較とレイヤーマップの適用](examples.md)、編集可能な構成は[Draw.io制作例](../assets/drawio-examples/catalog-layouts.drawio)を参照する。
