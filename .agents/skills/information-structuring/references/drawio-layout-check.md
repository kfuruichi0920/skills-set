# Draw.ioの配置とコネクター検査

精密モード、または表示検査を追加指定されたDraw.io図に適用する。高速モードでは本書の詳細な目視検査を省略し、その旨を記録する。[実行モード](execution-modes.md)の個別指定を優先する。テーマやXMLの整合検査だけで表示検査済みと扱わない。

## 検査場所と表示

production.mdのoutput参照規則に従い、今回新規作成したDraw.ioとプレビューはoutput内で制作・表示・検査・修正してよい。既存成果物を検査材料に使う場合は、ユーザーが参照を明示した対象だけを扱う。

ローカルのDraw.io表示環境またはレンダラーで、全ページを実際に表示する。図全体が見える倍率で経路・交差・領域の余白を確認し、通常の読取り倍率でも線・矢印・ラベルを確認する。書き出したSVG／PNGを検査する場合は、Draw.ioファイルからレンダリングした画像を使う。別途描き直したプレビューをDraw.ioの表示確認として扱わない。

## 各コネクターの点検

ページごとに全コネクターを点検する。接続先の図形ID・ラベルと、見えている経路を照合する。

- 始点と終点が意図した図形の境界に接し、図形の中央や本文を貫いていない。
- 関係のない図形・注釈・見出しを線が横切っていない。グループ内の線や境界を越える線は、その意味に応じた経路になっている。
- 図形同士の間に線、矢印頭、関係ラベルを置く余白がある。図形が接近し、線が隠れたり矢印だけになったりしていない。
- ラベルの両側で線の経路を追える。線が文字の背景に覆われ、関係名だけが浮いて見えていない。
- ラベルが図形、他のラベル、矢印頭、折返し点に重ならない。どの線のラベルか一意に読める。
- 複数の線が同じ経路を重なって進む場合も、本数・向き・接続先を区別できる。線の交差が接続点に見えない。
- 自己ループ、戻り線、条件分岐は主経路と区別できる。短い不要な折返しや、図形の外へ出てすぐ戻る経路がない。
- 矢印の向き、実線・破線、主経路の太さ、関係名が意味記号と一致している。

余白は文字量と線の本数から決める。ラベルの文字幅、矢印頭、前後の線分を収められない間隔は広げる。図全体を縮小して詰めるのではなく、キャンバスを広げるか、全体図と詳細図へ分ける。

## 修正と再検査

1. 重なった図形を移動し、工程・列・レーン間にコネクター用の通路を設ける。対応する図形の比較位置は保つ。
2. 接続辺や接続点を変更し、線の出口と入口を分ける。複数線を同じ点へ集中させる場合は、分岐・合流の意味が読めるか確認する。
3. 直交経路を基本に、必要な折返し点を指定して図形・ラベルを避ける。手動の経路指定は自動経路で避けられない箇所に使う。
4. ラベルを線の長い区間へ移す。文字背景が線を隠す場合は、ラベル位置・文字量・線分長を調整する。線から離す場合も対応する線が分かる位置にする。
5. 同じ経路の重複線を分離する。交差を減らすために配置を変え、残る交差は接続を示すものか単なる交差か分かる表現にする。
6. 修正後のDraw.ioを再レンダリングし、問題箇所と同じページ全体を再確認する。移動に伴う他の線の変化、ラベルの重なりも点検する。

接続先、方向、関係名、条件を、見栄えの修正のために変更しない。経路と配置を修正した後も、元情報IDとの対応を確認する。

## 完了条件と記録

根拠資料に、検査した図ファイル・ページ、表示方法と読取り倍率、コネクターの点検範囲、問題箇所、修正内容、再確認結果を記録する。全コネクターを確認したことと、未確認範囲を区別する。

ユーザーの読取り倍率で、接続先・線の経路・向き・関係ラベルを追え、図形との重なりや余白不足がないことを完了条件とする。レンダラーが利用できない場合はXML・座標・接続参照を検査するが、「見た目の確認は未実施」と記す。表示を確認できなかった図を視覚検査済みと報告しない。
