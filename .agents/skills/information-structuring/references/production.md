# 制作・保存・提出

出力形式と保存先を決めるときに読む。検査の深さは[実行モード](execution-modes.md)が正本。通常の利用ではGit操作を行わず、案件のoutputへ結果を保存する。

## 形式の確認

明示指定を優先する。未指定なら「Markdownを中心に、必要な図をPlantUMLまたはDraw.io、大きな表をTSVで添える構成を推奨します。この構成、HTMLスライド、テーブル中心のどれを希望しますか？ CSVも選べます」と質問する。回答待ちは情報整理を進め、形式に依存する制作は回答後に行う。確認済みの質問を繰り返さない。

シーケンスはPlantUML、構造・配置図はDraw.io、小さい単純構造は[ASCII等の規則](visualization.md)を使う。テーブルの区切り未指定はTSV。大きなマトリクスはMarkdown表に展開せずTSV／CSVを添え、本文には目的・軸・読み方とリンクを置く。

## 保存と参照

- プロジェクトルートへ`output/YYYYMMDD_HHMMSS_約20文字の日本語概要/`を新規作成する。日時はユーザーのローカル時刻。禁止文字を置換し、同名なら別名にして上書きしない。
- 既存outputは対象と参照目的が明示された場合だけ扱う。一般探索から除外し、過去のパスや更新日時を参照許可と見なさない。
- 今回作成したパスを記録し、そのファイルだけを制作・読戻し・検査・修正する。次の別の依頼では既存成果物として扱う。
- 主成果物、図、表、根拠、原図、IR、画像を同じ実行フォルダへ保存する。新規成果物の保存にgit status／add／commit／pushは不要であり、実行しない。

Draw.io制作で作成したPython等は一時版も削除せず`scripts/`へ残す。使用した同梱ツールと必要な依存ファイル、IR・設定も保持し、`generation.md`へ最終版・再実行コマンド・ランタイム・入力と出力を記す。不要な全カタログをコピーせず、利用に必要な抜粋はID・出所・版を保つ。一時作業場所への依存を残さない。

## 形式ごとの制作

### Markdown・Draw.io・PlantUML

`result.md`を主説明とし、図へ相対リンクする。Draw.ioはネイティブ図形・所属・表・関係・ラベルを使い、必要ならページを分ける。[図形選択](drawio-native.md)と[テーマ](diagram-themes.md)を適用する。見本SVGの転載だけで新規図制作を完了にしない。

既存図・画像の説明追加は[注釈規則](visual-annotation.md)に従う。原図を保持・ロックし、注釈を別層にする。原図を再配色しない。元ソースと注釈IRも保存する。

PlantUMLはUTF-8の`.puml`を正本として保持する。画像が必要ならSVG／PNGを同じフォルダへ生成する。参加者、順序、方向、条件を入力と照合する。レンダラーがなければソースを保存し、構文・表示の未確認を記す。

Draw.ioでは今回のXML、実図形ID、所属・接続参照、情報との対応を検査する。高速では詳細な表示検査を省き、精密では[全ページの配置検査](drawio-layout-check.md)を行う。

### HTML・PowerPoint

HTMLは単一ファイルを基本とし、ページをsectionで分け、図をSVG／HTMLで描く。PowerPointは利用可能な生成ツールで文字と図を編集できる要素にする。寸法・フォント・配色は目的と閲覧方法から選び、特定企業の設定を品質基準にしない。

高速ではファイル構造と内容対応を確認する。精密ではHTMLをブラウザー、PowerPointを画像／PDFで全ページ表示し、文字切れ・改行・図表対応を直す。PDF指定時はページ境界も確認する。表示環境がない場合は未実施と記す。

### TSV／CSV

列名、一定の列数、単位・期間・条件・出所を保持する。コピー用TSVは実タブ区切りとし、セル内のタブ・改行を正規化して変更を記録する。CSVのカンマ・引用符・改行は正しく引用する。UTF-8を使い、Excelへの直接読込みではBOMも選べる。

今回作成した表を読戻して列数と内容対応を確認する。先頭ゼロ・日付・長い数字の自動変換が問題になる場合は取込時の列型を補足する。大きい表のチャット掲載は抜粋にする。

## 根拠と提出

[rationale-template.md](../assets/rationale-template.md)を参考に、質問原文・入力時刻・出所・採用軸・表現の理由・出力対応・不明点・モードと検査状況を`rationale.md`へ残す。入力時刻が取得できなければその旨を記し、記録時刻と区別する。高速では該当項目だけ簡潔に書き、空の表や全候補の一覧を埋めない。補足の省略・別形式の明示指定は尊重する。

主成果物と根拠のリンクを提出する。省略した検査を明記し、素材にない数値・因果・仕様を足さない。形式の生成成功と表示の点検完了を区別する。
