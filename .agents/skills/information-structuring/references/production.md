# ファイル制作

形式の確認、出力先の作成、ファイル制作時に読む。スライドはキャンバスの一候補であり、選択した形式でも入力の意味と関係を保つ。

## 形式の確認

ユーザーの明示指定を優先する。主成果物はMarkdownを優先し、図が必要ならDraw.io、大きな表・マトリクスはTSV／CSVを補足として組み合わせる。これらは排他的な選択肢ではない。

未指定なら「Markdownを中心に、必要な図をDraw.io、大きな表をTSVで添える構成を推奨します。この構成、HTMLスライド、テーブル中心のどれを希望しますか？ CSVも選べます」と質問する。回答待ちは情報整理・軸の抽出・候補比較を進めてよい。形式に依存する制作は回答後に行う。既に指定・確認済みなら質問を繰り返さない。

テーブルの区切り形式が未指定ならTSVを使い、その選択を伝える。CSV希望や取込先の制約がある場合はCSVを選べる。PowerPointなど別の形式を明示された場合も尊重する。

## 保存先

作業対象のプロジェクト／ワークスペースのルートに`output`ディレクトリを作成する。成果物を保存する段階で、その下に`YYYYMMDD_HHMMSS_日本語概要説明文`を作成する。日付と時分秒は実行時のユーザーのローカル日時を使用し、概要は内容を識別できる日本語約20文字にする。

例: `output/20261004_143205_申請業務の状態と責任分担の整理と可視化/`

概要中のパス区切り・OSで禁止される文字は除去または置換する。同名が存在すれば時刻を取り直し、必要なら末尾に連番を付け、別実行の成果物を上書きしない。一回の実行では同じフォルダを使い、主成果物、編集可能な図、TSV／CSV、補足の`rationale.md`、必要な画像や付録をすべてそこへ保存する。提出時に出力フォルダと各主成果物・補足資料のリンクを示す。

## 出力条件

資料の目的、情報量、閲覧方法、指定されたテンプレートからページ寸法・文字サイズ・配色を選ぶ。特定の企業・作者のデザイン値を既定の品質基準にしない。明示指定がなければ一般的な横長スライド比率を出発点にしてよいが、情報構造に合う比率を選べる。

日本語の本文・見出し・図表ラベル・補足にはjapanese-writing.mdを適用する。形式によって短縮しても、条件・例外・関係種別・確かさを保つ。

実行環境とライブラリを確認する。Codexデスクトップではload_workspace_dependenciesを利用できる。利用できない機能を実行済みとして扱わず、途中成果と不足条件を伝える。

## HTML

単一HTMLで閲覧できる形を基本に、ページをsectionで区切る。図表はSVGまたはHTMLで作り、全体の比率と文字の可読性を保つ。外部フォント・画像を使う場合は代替や依存を確認する。

ブラウザーで全ページを表示し、ラベル・改行・図表対応を検査する。印刷やPDFが指定された場合はページ境界も確認する。PNG出力が必要なら用途に合う解像度を選ぶ。

## 編集可能なPowerPoint

環境で利用可能なpython-pptx、PptxGenJS等を使う。文字はテキスト、図は標準図形または編集可能なグラフにする。画像が適切な内容のみ画像を使う。

座標は出力先の幅・高さに対する比率で変換する。配色変更が必要な場合は、テーマまたは生成パラメーターに色の役割をまとめる。フォントの代替で改行が変わることを確認する。

PDFまたは画像へレンダリングして全ページを検査する。レンダラーがない場合はファイル構造を検査し、視覚確認が未実施と明記する。

## Markdown + Draw.io

整理結果・説明・候補比較を主成果物の`result.md`に保存する。必要な補足図は編集可能な`diagram.drawio`として保存する。可視化の選択とASCII図の利用はvisualization.mdに従う。Draw.ioの図はネイティブの図形・接続線・テキストで構成し、情報ID・関係・条件・凡例を保持する。Markdownから図のファイルへ相対リンクし、必要ならプレビューも同じフォルダに添える。

XMLとして読めること、図形IDと接続先の整合、ラベルと図の対応を検査する。表示確認ができる環境では図全体を開いて確認し、表示確認できない場合はその範囲を明記する。

## テーブル（TSV／CSV）

大きな表、行列の対応・網羅的比較・属性データを表すマトリクスは、Markdown表に展開せずTSV（CSVも可）を使う。少数の候補を説明する小さな表はMarkdownでよい。固定の行数だけで判定せず、列数・セルの長さ・全量の確認や再利用の必要性で決める。Markdownには表の目的・軸・読み方・ファイルへのリンクを置き、必要なら小さな抜粋を載せる。全量はTSV／CSVを基準とする。

Excelへの直接コピーを優先し、TSVは実際のタブでセルを区切り、改行で行を区切る。`.tsv`ファイルを保存し、チャットに載せる場合もMarkdown表に置き換えず、コピー用コードブロック内へタブ区切りで載せる。大きな表はファイルを主成果物とし、チャットは抜粋にする。

先頭行は列名、各行は同じ列数とし、単位・期間・条件・出所を必要な列または補足に残す。コピー用TSVのセル内のタブと改行は空白などへ正規化し、意味のある箇条書きは行に分ける。正規化の内容は補足へ記録する。CSVはカンマ区切りとし、カンマ・引用符・改行を含むセルを正しく引用する。

UTF-8で保存し、Excelでファイルを直接開く用途ではBOM付きUTF-8を選べる。識別子の先頭ゼロ・日付・長い数字などはExcelの自動変換に注意し、必要な取込時の列型を補足する。保存後に区切り形式で読み戻し、列数と元情報への対応を検査する。

## 提出

求められた形式の実ファイルへのリンクを示す。案の軸・主案の選択理由・重要な留保は資料内に残す。完成度にかかわらず、素材にない数値や固有の出来事を足さない。

## 情報構造を保つ出力

表や構造化データでは情報ID・関係種別・条件・出所を保持する。図では同じ情報を共有IDで対応付ける。ページ分割で条件や例外が離れる場合は参照を付け、全体と詳細の対応を残す。ユーザーがMarkdown単独を明示指定した場合も、その形式で情報整理を完了できる。

## 整理根拠の補足資料

主成果物の形式によらず、rationale-template.mdに沿う別のMarkdownを標準で添える。入力出所→情報単位→整理軸→候補と採否→出力要素を追えるようにし、省略・集約・不明点を記録する。出力ファイルと補足資料を相互参照する。ユーザーが補足を省略・別形式に指定した場合は従う。
